{{- if not .Values.enabled }}

STOPPED: enabled=false. Every Deployment and the Postgres StatefulSet are at 0 replicas and the
data Job is not rendered. Volumes, Services and the Secret are untouched. Start it again with
`helm upgrade ... --set enabled=true` (or enabled: true in your values); that revision's data Job
re-runs the idempotent seed and dbt steps.
{{- else }}

Secret {{ .Values.secrets.name }} must exist with MCP_AUTH_TOKEN and POSTGRES_PASSWORD.
{{- if or .Values.seed.enabled .Values.dbt.enabled }}

The data Job ({{ $job }}) seeds and builds the marts. A first install embeds every transcript
(minutes with a hosted embedding API, about 45 minutes on 2 CPU cores with Ollama); later
revisions reuse the stored vectors.
  kubectl -n {{ .Release.Namespace }} logs -f job/{{ $job }} -c {{ ternary "seed" "dbt" (and .Values.seed.enabled (not .Values.dbt.enabled)) }}
  kubectl -n {{ .Release.Namespace }} wait --for=condition=complete --timeout=3h job/{{ $job }}
{{- end }}

The mcp-server pods wait in Init until the data is in place, then serve /mcp and /healthz:
  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ $mcp }} --timeout=3h
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ $mcp }} 8000:{{ .Values.mcpServer.service.port }}
  MCP_SERVER_URL=http://127.0.0.1:8000/mcp MCP_AUTH_TOKEN=<token> python -m ccai_mcp.http_smoke
{{- if .Values.cloudflared.enabled }}

cloudflared is running with the token in Secret {{ .Values.cloudflared.tokenSecret.name }} (key {{ .Values.cloudflared.tokenSecret.key }}).
In the Cloudflare dashboard, set the tunnel's public hostname to forward to this origin:
  http://{{ $mcp }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.mcpServer.service.port }}
{{- end }}
{{- end }}
